# Finite queue acceptance specimen

Declared before executing either arm, October 13, 2026. All principals, jobs,
acquisitions and needs are synthetic. This is Package C's Stage-1 learning
experiment, not a grant, a live observation or a commercial service.

The caller asks for title starting with the case-sensitive literal `Data ` AND
location exactly `Remote US`. Required output fields are title, location, URL,
source and fetchedAt. This new predicate has no relationship to the old
Firecrawl request's unknown Boolean filter. Normalizers and fetch functions
remain byte-identical to the pinned accepted free recipe.

Three distinct caller tasks, inputs and freshness needs are bound in queue.json.
The acceptance oracle in expected.json was written before execution:

| Input | Expected whole answer | Acceptance |
| --- | --- | --- |
| input-1, listed Ashby response | Data Platform Engineer; one unlisted role withheld | Accepted selected row, complete only for returned listed set |
| input-2, two Workday roles | No matching rows | Accepted covered empty selection, not an empty board |
| input-3, Workday later-page 503 plus unreadable row/location | Data Engineering Fellow retained; null-location row and missing title/path retained as unknown | Explicit partial, unresolved; never an empty success |

Acceptance requires unchanged bytes and source/predicate binding, a declared
need whose notBefore is covered by acquiredAt, complete declared coverage, and
no unreadable row or unknown predicate field. A digest establishes byte
identity only. It establishes neither source truth nor caller authority.
Ashby coverage concerns its returned listed set, not all jobs elsewhere.

Missing need is unknown. An already accepted identical source/predicate/input
with the same need is not_yet_due. A separately declared need with a different
ID can be due even when rows are unchanged, provided its declared freshness
floor is covered. Source/predicate changes are requalification, never reuse of
old acceptance. This determination executes no purchase or renewal.

Both arms receive the identical complete acquired graph, queue, fixtures,
predicate, oracle, source knowledge, limits and output requirements. Ordinary
filter/file transformations are available to the direct arm. The candidate
arm is finite responsibility through the same direct recipe. If this closes
both whole outputs, disposition is executed no-delta; no second consumer,
extraction adapter, execution engine, endpoint or priced wrapper is warranted.

Bounds: three unique inputs, six raw queue entries including duplicates,
16 KiB queue, 64 KiB per snapshot, 192 KiB aggregate snapshot bytes, six
aggregate requests/pages and 45 seconds declared acquisition elapsed. Recipe
bounds stay six requests/four pages/15 seconds per observation, 1,000,000 bytes
per response and manual redirects. All acquisitions here are offline; fault
fetches are injected and never contact a board. One finite correction round,
then unresolved inputs return to the caller. There is no timer or retry loop.

Atomic output replacement is an ordinary file transformation: an interruption
before rename leaves the old file intact, an interruption after rename is
resolved by readback, and a deterministic rerun cannot append/count inputs
twice. A conflicting existing result is refused. The receiver remains Node's
unchanged JSON.parse/file interface; it need not install a plugin or library.

Synthetic decline and changed terms before a proposed paid action produce
no action. No account, customer input, paid route or production activation is
part of either arm. Support, future upkeep, adoption, profitable demand and
settled revenue remain unknown. The later consumer is an agent with a genuinely
new public-data queue; lower qualification/correction effort requires a later
distinct receiving observation, not this single mechanical comparison.
